# 2026-11-14

- 修复：在 acp-service 里选择 Cursor Agent 时，会话在创建前就被拒绝，界面只显示 “ACP execution failed.” 和重试。Cursor 的 ACP 会公布 `cursor_login`，并且在客户端调用 `authenticate` 之前拒绝 `session/new`；这条方法用的是本机 `agent login` 的登录态，不是 ACP 凭据。运行时以前只在找到 API 凭据时才认证，于是跳过了 `cursor_login`。现在 `cursor-agent acp` 和 `agent acp` 会在建会话前发送 `cursor_login`，不读取 ACP 凭据。其它 Agent 即使公布同名方法也不会被当成 Cursor。尚未执行 `agent login`、也没有 `CURSOR_API_KEY` / `CURSOR_AUTH_TOKEN` 时，认证仍会失败。
- 验证：对本机已登录的 Cursor CLI 复现，未认证时 `session/new` 返回 `Authentication required`；补上 `authenticate` 后能创建会话。`packages/runtime` 的 Cursor 认证单测覆盖 `cursor-agent acp`、绝对路径 `agent acp`，以及非 Cursor 命令在 `authPolicy=fail` 下仍拒绝该方法。
