# 2026-11-23

## 调整

- 移除 DSH 插件对聊天记录区的自绘。`packages/dsh-plugin/src/transcript-view.js` 不再替换 `conversation.chat.node` 的 `assistant-step`，也不再插入隐藏原生过程组的样式。`tool-conversation.js` 不再把同一轮 ACP 输出投影成第二条助手消息和自定义工具组。正文与思考仍写入 DSH 原有的 assistant 流，由 DeepSeek Harness 自己的聊天界面渲染。远程工具调用仍作为不含可见文字的 `acpTool` 记录留在流里，不会变成本地工具调用，聊天区也不再显示插件自己的「已调用 N 个工具」。只含工具、没有正文的轮次因此不再出现「Bash, Bash」这类摘要行。模型选择控件未改。
- 调整：ACP 外部 Agent 会话（如 `oneagents-acp-antigravity`、`codex`、`claude` 等）的输入框模型与原生配置控件升级为官方同款胶囊样式 + 两级 Popover（`packages/dsh-plugin/src/model-select.js` 新增 `AcpModelSelect`，`packages/dsh-plugin/src/client.js` 移除原生 `<select>`）。触发器展示当前模型与思考强度（如 `thought_level`），展开后按两级菜单钻取切换模型（超过 4 项带搜索框与分组）、思考强度、模式及其他原生配置，操作失败改走官方 `Toast` 与菜单内重试提示。

## 新增

- 新增：DSH profile 安装或加载 `@1agents/acp-service` 时，若本机全局 `acp-service`（`npm root -g`）版本不同，用当前这份包执行 `npm install -g` 覆盖。工作区源码安装和已带 `ACP_SERVICE_SKIP_GLOBAL_SYNC=1` 的嵌套安装不会再装一次。全局安装失败只记警告，不阻止插件启动。设 `ACP_SERVICE_SYNC_GLOBAL=0` 可关闭。
- 新增：`remote_agent_model_catalog`。CLI（`acp-service a2a invoke`）和 DreamMate/MCP 用 `remote`、`originSessionId` 读取执行宿主 standard 的当前模型目录：默认路由、各 provider 下可填写的 model id、routing group 标记和推理等级。不创建会话、不调用模型。宿主走与 preflight 相同的 A2A 凭证，路径为 `/a2a/model-catalog`，内部调用已有的 `sessionController.modelCatalog()`。provider 拉取失败只返回 id 和名称，不返回上游报错原文。正在运行的网关和桌面端要重启后才会提供这个方法。

## 修复

- 修复：`remote_agent_spawn` / `remote_agent_message` 显式传入 `provider` 与 `model` 时，DSH routing group（如 `magpie` / `group/daily-choice`）会在几十毫秒内失败，任务结果只剩 “ACP execution failed.”。省略这两个字段时仍走宿主默认路由，所以同一条平价路由显式指定反而不可用。现在目录中的模型、名称含 routing group 的条目，以及宿主当前默认路由，都按会话自己的模型选择记录；`resolveCallConfig` 把 routing group 或带 `/` 的模型 id 当成精确模型拒绝时，不再中断选择。未知的 provider/model 在建会话前失败，`resultMetadata.validation.code` 为 `UNKNOWN_MODEL_OR_GROUP`，结果文字给出所请求的 id 和最多 12 个目录项。宿主接受了路由但没能写上时，仍是 `MODEL_UNAVAILABLE`，但不再被收成通用失败句。省略 provider/model 的旧调用不变。
