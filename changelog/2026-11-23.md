## 修复

- 修复：A2A 执行器不再在 `oneagents-acp-*` 会话准备前无条件写入误导性的 `Pending: waiting in FIFO order for device memory and ACP capacity.`（改为先发普通 `TASK_STATE_SUBMITTED`，仅在实际进入任务/内存或进程名额 FIFO 排队时才发布排队提示）；同时 `HeadlessDshBackend`（`@1agents/dsh-a2a`）拒绝非 `standard` 预设与请求级 `provider`/`model` 时分别抛出 `PRESET_UNSUPPORTED` 与 `MODEL_SELECTION_UNSUPPORTED`，`A2ASessionExecutor` 保留宿主白名单内的明确原因文案并写入 `resultMetadata.validation.code`，不再收成泛化的 “ACP execution failed.”。
- 修复：`acp-service` 新增并升级第一阶段「智能体感知分级回收 + 压力驱动按需驱逐」机制：默认交互会话（`user-opened`）空闲 5 分钟回收（`ACP_IDLE_SESSION_TTL_MS`，`0` 关闭定期回收），后台 A2A 任务（`job`）空闲 60 秒回收（`ACP_IDLE_JOB_TTL_MS`）；新会话申请进程名额遇槽位/内存不足时，按「断连 WS → 后台 `job` → 交互 `user-opened`（同级 LRU）」顺序按需逐个驱逐满足宽限期（`ACP_PRESSURE_EVICT_GRACE_MS`，默认 15s；`ACP_PRESSURE_EVICT_ENABLED=0` 可关）的空闲会话并推送 `reason: "capacity_evicted"`。同时完善 `sessionBackgroundTasks` 的入库与更新，将运行中后台任务纳入 `isSessionBusy` 保护集合（因 `runtime.close()` 会连同后代进程一并终止，避免误杀会话内运行中后台子进程）。`acp-connection.ts` 与 `dsh-plugin` 同步支持 `idle_timeout` / `capacity_evicted` 后的无感关闭与 `session/load` 接回。
- 调整：更新 `packages/service/skills/acp-service/`（并同步构建到 `packages/dsh-a2a/skills/acp-service/`）中的 `SKILL.md`、`references/a2a.md`、`references/roles-and-tasks.md` 与 `references/acp.md`，明确区分 `@1agents/acp-service` DSH 插件宿主（`DshA2ABackend`）与独立 `@1agents/dsh-a2a` 宿主（`HeadlessDshBackend`）在 `agentPreset`、`provider`/`model` 和错误码上的能力边界，补充说明独立纯 DSH 宿主不走 ACP 的架构考量（避免维护两套消息通知体系、简化系统保障长期稳健性；早期双轨为过渡策略，现明确收紧先确保 `standard` 跑通，后续再视情况评估是否放开 ACP），以及 `acp-service` 空闲进程回收参数。
- 修复：`remote_agent_spawn` / `remote_agent_message` 显式传入 `provider` 与 `model` 时，DSH routing group（如 `magpie` / `group/daily-choice`）会在几十毫秒内失败，任务结果只剩 “ACP execution failed.”。省略这两个字段时仍走宿主默认路由，所以同一条平价路由显式指定反而不可用。现在目录中的模型、名称含 routing group 的条目，以及宿主当前默认路由，都按会话自己的模型选择记录；`resolveCallConfig` 把 routing group 或带 `/` 的模型 id 当成精确模型拒绝时，不再中断选择。未知的 provider/model 在建会话前失败，`resultMetadata.validation.code` 为 `UNKNOWN_MODEL_OR_GROUP`，结果文字给出所请求的 id 和最多 12 个目录项。宿主接受了路由但没能写上时，仍是 `MODEL_UNAVAILABLE`，但不再被收成通用失败句。省略 provider/model 的旧调用不变。
- 修复：Antigravity 从旧 `agy_acp_server.par` 切到 `agy acp` 后，思考档位选项由 `thinking_level` 改名为 `thought_level`。旧会话钉住的 `thinking_level=medium` 在新目录里校验失败并阻止新会话打开（`Pinned ACP option "thinking_level" is not advertised by antigravity`）。`packages/dsh-plugin/src/session-settings.ts` 现在按 agent 迁移已保存的选项 ID（保留原值和 `model` 标记；已有显式新 ID 钉住时以新 ID 为准），旧设置自动落到 `thought_level`；本机 `~/.dsh/plugins/1agents-acp/sessions/agent-session-settings.json` 已同步改名，重新打开本工作区的 Antigravity 会话即可恢复 `medium` 档位。
