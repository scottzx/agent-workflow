# 2026-11-24

## 调整

- 调整：`@1agents/acp-service` 仍是唯一公开包，runtime 与 DSH 插件继续在构建时嵌入 `vendor/`，不另发 npm 包。`scripts/verify-package-build.mjs` 改为对照源码树检查嵌入内容，而不只确认文件存在：`vendor/dsh` 必须与 `packages/dsh-plugin/dist` 及 `cordis.patch.yml`、`README.md`、`LICENSE` 字节一致；`vendor/runtime` 必须等于对当前 `packages/runtime` 做同一 SDK 别名与 flow 入口改写后的结果。少一字节、runtime 未改写或 SDK 别名范围不一致时，`prepack` 与 `node scripts/embed-dsh.mjs` 失败。CI 的 `dsh-plugin` 作业在校验前恢复同一构建上传的 runtime `dist`。
- 调整：去掉 `@1agents/dsh-a2a` 未使用的 `@1agents/acp-runtime-sdk`（`npm:@agentclientprotocol/sdk@^1.5.0`）。ACP SDK 只保留两处钉死：service 与 DSH 插件的 `@agentclientprotocol/sdk@1.4.0`，以及 service 上跟随 runtime 的 `@1agents/acp-runtime-sdk` → `sdk@^1.9.0`。`dsh-a2a` 仍在构建时打包 `a2a-standalone`，运行时不依赖 ACP SDK。
- 调整：删除根 `.github/workflows/release.yml`。`@1agents/acp-service` 只从 `publish-npm.yml` 用 npm 可信发布（OIDC）发出 CI 已有 tarball，不再保留共用 `npm-release` 并发组的 `NPM_TOKEN` 入口。`packages/runtime` 内的上游 acpx 发布文档未改。

## 修复

- 修复：ACP 会话在进程被空闲回收后重新 `session/resume` 时，如果上次保存的模型已经不在 agent 本次广告的目录里，不再把整次接回判失败并关掉刚拉起的进程。回放改为跳过这次模型选择，沿用 agent 当前默认模型，提示可以继续发出；保存的模型 id 留着，目录里重新出现时再回放。显式指定一个不存在的模型、agent 完全不广告模型能力、以及 `setSessionModel` 本身失败，仍按原来的方式失败。Antigravity 在目录从含 `gemini-pro-orchestrator-g1-pro` 变成不含该 id 时，冷启动 resume 会走这条路径。此修复随补丁 `@1agents/acp-service@1.0.1` 发布，相对 `1.0.0` 没有新的不兼容变更。npm 发布完成前不记为已上架。

- 修复：DSH 分叉 ACP 会话时，`applyPinnedSettings` 回放钉住的模型；如果 Antigravity 升级 `agy acp` 后目录里已没有该模型 id，原来直接报 `Pinned ACP option "model" value "..." is not advertised by antigravity` 并终止分叉。现在模型钉选遇到目录不匹配时跳过，沿用 agent 当前广告的模型，其他钉选项仍按原样严格校验。与上面的 runtime resume 修复配套，走同一份 `1.0.1` 补丁。

## 不兼容变更

- `@1agents/acp-service` 由 `0.11.4` 升至 `1.0.0`。npm 上依赖 `^0.11.4` 的安装不会自动升到 `1.0.0`。包名、命令名 `acp-service`、exports、环境变量和 `.1agents/` 不变，公开安装物仍是这一个包。`packages/runtime` 保持私有 `@scottzx/1acp@0.16.0`，不单独发布。
