# 2026-11-11

- 调整：服务目录把 Antigravity 当成已接入的 ACP Agent，不再把 `agy` CLI 当成 ACP 运行时。`packages/service/src/catalog-descriptors.ts` 的 `acp_capable` 和 `integrated` 改为 true，`cc_transport` 改为 `acp`，安装说明改为同一发行版里的 `agy_acp_server` 与 `localharness_external`。`packages/service/src/catalog.ts` 在 Windows 上探测 `agy_acp_server.exe`，其他平台探测 `agy_acp_server.par`。只装 `agy` 时 `installed` 和 `chat_ready` 都是 false；ACP 运行时在 PATH 上时两者为 true。
- 限制：acpx 仍会取消 Antigravity 通过 `session/request_permission` 发出的固定选项提问（toolCallId 以 `interaction_` 开头）。`--approve-all`、权限策略和宿主权限回调都不会代选答案。普通工具权限照旧。这类对话要在能回答提问的交互客户端里继续。
- 验证：`packages/service/test/catalog.test.ts` 覆盖只装 `agy` 时不算就绪，以及 darwin 的 `agy_acp_server.par` 和 Windows 的 `agy_acp_server.exe` 被识别为可启动。
- 发布：`@1agents/acp-service` 版本改为 `0.10.1`。npm 发布走 `main` 上的 Publish npm 工作流，使用 CI 产物和可信发布，不在本机直接 `npm publish`。
