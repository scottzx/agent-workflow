- 新增：工作台“智能体”页可以按路径登记智能体。填一个目录、ACP Agent 和执行连接后，网关读取该目录下的 `agents/*.md`（Claude Code、Grok 原生认的插件格式，frontmatter 里的 `name`、`description` 加正文），每个文件登记成一份开发中的草稿和一个执行目标 `path:<目录哈希>:<name>`。这个目标是 `agent_host`，`cwd` 固定为该目录，预设固定为 `oneagents-acp-<ACP Agent>`，并绑定新字段 `agentFile`；调用方不能覆盖 `cwd`、预设或角色。同一目录再登记一次会按文件更新原有草稿和目标，任务记录不丢。之前工作台只扫描 `.1agents/roles/*/profile.json`，所以 `trajectory-restore` 的 `restore-executor`、`restore-qa` 不出现在任何列表里。
- 新增：派单到路径智能体时，网关在新会话的第一条消息里带 `metadata.1agents.agentFile`；执行宿主在会话的真实 `cwd` 里重新读取并校验这个文件（必须是 `cwd` 内、不超过 64 KB 的 `.md`，不能和宿主角色同时使用），把正文作为角色说明加在 prompt 前面。续派不再重复加。接口：`POST /workbench/agents/register-path`，`GET /workbench/agents` 多返回可选的 `connections`。不兼容变更：未升级的执行宿主会把 `agentFile` 当作未知字段拒绝，所以网关和宿主要一起升级。DSH 原生预设也可以登记：表单里“运行方式”选“DSH 原生预设”，填预设（默认 `standard`），可选填 `provider/model`，比如 `minimax-cn/MiniMax-M3.1-Flash`。模型固定在目标的 `binding.provider`、`binding.model` 上，派单时带给宿主，宿主按模型目录核对，目录里没有就失败、不回退默认模型；调用方不能再改。只有路径智能体的非 ACP 预设能固定模型。同一目录可以在 ACP 和 DSH 原生之间重新登记，原草稿和目标随之更新。Codex 的原生角色加载仍没有接。新增测试 `packages/service/test/a2a-path-agent.test.ts`，`workbench-gateway.test.ts` 补了 ACP 和 DSH 原生两条；未部署，也未在真实宿主上派过任务。
