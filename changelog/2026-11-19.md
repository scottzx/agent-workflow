## 修复

- prompt 失败的 `SafeError` 投影此前把 `SessionResumeRequiredError` 归入 `unknown` 档（文案变为 "ACP execution failed."），丢失恢复语义；现按 `detailCode` 放行静态安全句 "Persistent ACP session record could not be resumed."，对齐上游显式恢复契约（`test/runtime-explicit-resume.test.ts`），动态 session id 与 reason 仍不外泄到桥接输出。
- service 适配器发现（`localLaunch`）按上游 [`#922`](https://github.com/openclaw/acpx/pull/922) 的 npx 形态（`--package=<spec>` + bin 选择器）提取包名，兼容旧位置参数形态；修复融合后工作区 `node_modules` 适配器包丢失优先级（被 PATH shim 或 npx 回退抢占）的问题，`packages/service` catalog 测试断言随新形态微调。
- `packages/service` 依赖区间对齐 embed 断言：`@1agents/acp-runtime-sdk` 别名 `^1.5.0`→`^1.9.0`、`@openclaw/fs-safe` `^0.26.7`→`^0.28.0`、`zod` `^4.6.5`→`^4.6.7`（service 自有 `@agentclientprotocol/sdk` 1.4 隔离不变）。
- 弃连的 ACP 连接此前不归还容量名额：客户端直接断开 WebSocket 而不发 `session/close` 时，agent 子进程与它占的 process 租约一直留存，累计到 softLimit（8）后新会话只能排进无超时的容量队列，`session/new` 永久挂起。现由 `attachAcpConnection` 的 close 回调在宽限期（`ACP_DISCONNECT_GRACE_MS`，默认 30s）后对仍归本连接的会话发 `close_session`，子进程退出、租约随 runtime 的 `onExit` 归还；宽限期内重连并被 `session/load` 重新接管的会话不受影响。
- 同期排查确认 `capacity.ts` 的 `readReservations` 回收条件（owner 与 child 同时死亡）**不需要改动**：真实 `kill -9` 子进程后租约在 1 秒内自动归还（`createCapacityLifecycle` 的 `onExit` → `release`），而 `test/capacity.test.ts` 里「live owner 不回收已退出 child」是覆盖 exit→观测窗口的故意设计。
- 归档会话不回收进程：DSH 归档只停掉会话的工作，ACP 进程与其设备容量槽在 service 守护进程里，归档动作到不了那里。新增 `AcpAdapter.releaseArchivedSessions()`，并由 `dsh-plugin` 在 `ctx.workspaceRegistry.archivedSessionIds` 上做 2s 轮询（`DSH_ACP_ARCHIVE_SWEEP_MS` 可配，0 关闭），命中已归档会话即发 `session/close` 并核对 `processReleased`；未归档会话不受影响。
- 容量耗尽时交互式开会话会无限排队：`processCapacity.tryAdmit` 在 softLimit 占满时只回 `CAPACITY_PENDING`，客户端按 750ms 一直重试，最终以笼统的传输错误收场。现在 `origin: "user-opened"` 的会话先读容量快照，`availableAutomatic < 1` 时立即回 `ACP_CAPACITY_SOFT_LIMIT` / `ACP_CAPACITY_HARD_LIMIT` / `ACP_CAPACITY_MEMORY_LIMIT`（带 `used`、`limit`、`availableSlots` 等读数），消息直接说明原因与处置方式；A2A 后台任务（`origin: "job"`）仍按 FIFO 排队。ACP 适配层对该族错误码放行本地文案并以 `-32011` 返回，绕过 `toSafeError` 的静态摘要。

## 不兼容变更

- 上游 events 解析入口改名 `runtimeEventFromMessage(message)`，自定义事件解析器签名变为 `(payload, meta?)`；下游若直接依赖旧的 `parsePromptEventLine` 需迁移。
- 队列 owner 启动失败判定、无效选项报错格式（`[acpx] error: USAGE` 单行）等 CLI 输出行为随上游调整。
- 弃连语义变化：WebSocket 断开不再等同于「会话继续存活」。超过 `ACP_DISCONNECT_GRACE_MS`（默认 30s）仍未重连接管的会话会被关闭，正在执行的轮次随之取消；依赖「断开后长时间保留活进程」的客户端需改用显式 `session/close` 或在此窗口内重连。
- 交互式开会话不再排队：容量达 softLimit 时立即返回 `-32011`（`ACP_CAPACITY_*`）并说明占用与处置，而不是等空位；需要排队等待的只有 A2A 后台任务。客户端若把 `CAPACITY_PENDING` 当作可无限重试的信号，不会再收到该状态下的 pendding。
- 归档会话会终止其 ACP 进程：归档后该会话的 ACP 进程被主动关闭，重新打开需重新拉起（冷启动）；这是归档语义的一部分。
