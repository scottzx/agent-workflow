## 调整

- [会话生命周期核对记录](../docs/a2a-session-lifecycle-close-resume-20261026.md) 改为代码核对记录，并指向上述收口方案。原文的代码位置和问题描述保留。
- 同日补充收口方案：网关 one-shot 只调用 runtime 已有的普通 `close`，ACP 会话继续 `ensureSession({ mode: "persistent" })`。关闭后由现有 `session/load` 或 `session/resume` 接回，不新增 `remote_agent_resume`。`standard` 预设没有 ACP 子进程，不对其发 `session/close`。
- 再补入三件实测：进程名额等待被 DSH 适配器 `session/new` 的 60 秒超时包住，满额时变成 `ACP_TURN_FAILED`；闲置会话可停在 accepted 且模型不跑，增加 5 分钟停滞看门狗；Codex `session_send` 的 accepted 只代表 `codex queue` 入队，桌面端未执行时改为 `queued`。口播使用 `closeAfter: "terminal"`。P1 发布同时带上 0.8.3 到当前源码的差异，重启 DSH 前要单独确认。
- persistent 会话增加默认空闲回收：回合结束并确认空闲后 600 秒没有后续，由网关做普通 close。`idleTtlSeconds: 0` 不回收，正数覆盖默认值。正在执行、`INPUT_REQUIRED` 和状态未知的不关。5 分钟看门狗仍只报 `STALLED`。该回收在 P3，上线前不会生效。
- 收口方案补上 persistent 从 spawn 到这一轮答完的顺序：任务名额、空白 DSH 会话、进程名额、grok 启动、回合保留。答完时进程仍在；600 秒回收从这之后才开始计。
- 按这条时间线重排实施顺序：P1 同时做终态关闭和把 60 秒移出排队，并在 `CAPACITY_PENDING` 里带队列位置与已等时长；P1.5 分开报告任务名额和进程名额，进程租约记预热、job 或用户打开；P2 先复现凉会话，撤回尚未定位就采用的 5 分钟 `STALLED`；P3 保留 600 秒回收，并为 `INPUT_REQUIRED` 增加 2 小时只告警。G8 改为单独立项，不进这次发布。省略 `idleTtlSeconds` 仍是 600 秒。
- 记下 G9：`standard` 派单不能指定模型，`sessionController.create` 只收 cwd 和 preset，执行器不调用 `selectModel`。训练师核实当前因此落到 MiniMax-M3.1-Flash，DSH 里的 DeepSeek 选不到，两份派单未跑。不排进 P0–P3，本轮也不改宿主默认模型。
- DSH ACP 会话不再把桥接三态 `permissionMode`（`approve-reads` / `approve-all` / `deny-all`）发给 `session/new` 或原生导入，桥接权限回调也不再按它自动放行或拒绝。模式和思考强度走 Agent 公布的 ACP 设置：界面选择或导入原会话后的 `session/set_mode` 与 `session/set_config_option`。`sessionPolicies.initialModeId` 仍在新会话首条 prompt 前设置已公布的原生模式。旧配置里的 `permissionMode` 仍可加载，但不再生效。Grok 的原生 mode 判定保持不变。
- 新增 [Grok 权限模式与工作台的两类人工事项](../docs/grok-mode-and-workbench-requests-20261027.md)。记录六个 mode 里只有 `bypassPermissions` 不会让分发任务停在工具审批上，以及工作台在现有结果验收之外接入提问和计划审批的方式。当日随后按该说明实现过程请求，见下一条。
- 工作台增加过程请求，和结果验收分开保存。网关派发时在 `metadata.1agents.execution` 带上 `{ jobId, attemptId }`。DSH 只在该回合内绑定。配置了 `a2a.workbench` 时，提问和计划审批与 DSH 的 `userQuestions` 竞速，先到的答复完成原来的等待，不另发 A2A 用户消息。5 分钟后过期，晚到的提交被拒绝。工具权限卡片、六页人审预览，以及试跑后固定 mode 与思考强度，都不在这次改动里。工作台凭据不进入 A2A metadata。
- 记下工作台的下一层结构，见 [工作台的智能体开发阶段与运行阶段](../docs/agent-workbench-phases-20261027.md)。任务与智能体同级。智能体分开发中和已上线。试跑任务与正式任务都进入同一任务清单和同一待我确认。发布在智能体模块完成，试跑审核通过不会自动上线。页面、投影和命名发布存储都还没改。
- 工作台增加与任务同级的智能体模块。网关用 `agent-registry.json` 保存每个 ACP Agent 自己的开发草稿，以及发布时冻结的一行名字、modeId 和有序选项。新任务在受理时打上试跑或正式并冻在该次执行上，续跑不改标记。常驻角色没有草稿时出现在已上线。父应用任务清单增加试跑、正式、临时，详情可回答过程请求。审核通过不会发布。`execution_submit` 仍不携带这些选项。发布结果还没有写入 DSH 的 `agent-session-settings.json`，宿主仍回放该工作区和 Agent 最近一次已接受的 ACP 设置。见 [工作台的智能体开发阶段与运行阶段](../docs/agent-workbench-phases-20261027.md)。
- DSH 插件把试跑时 ACP 设置里已接受的模式和配置选项，按工作区绝对路径和 Agent 名称写入状态目录的 `agent-session-settings.json`。Grok Build 与 Codex 各自保存自己公布并被接受的 mode id 和配置 id，例如 Grok 的 `reasoningEffort` 与 `bypassPermissions`，Codex 的 `verbosity` 与它自己的 mode。新建会话在首条 prompt 前回放：模型在前，其余选项按保存顺序，并用每次 `session/set_config_option` 返回的新目录检查下一项，模式最后。目录缺少当初的 id 或值时，在 prompt 前失败并关闭刚创建的远端会话。已有会话和导入会话不重复套用。没有试跑记录时仍只套用 `initialModeId`。记录里已有 mode 时使用该 mode。`execution_submit` 不增加这些字段。此前过程请求那条所说的试跑固定，现已按 Agent 分开实现。见 [Grok 权限模式与工作台的两类人工事项](../docs/grok-mode-and-workbench-requests-20261027.md)。

- 按 [A2A 缺口收口方案](../docs/a2a-gap-closure-plan-20261027.md) 实现 P0、P1、P1.5，以及 P3 的空闲回收、`INPUT_REQUIRED` 告警和计数。回调地址暂不可用时网关照常启动，回调端口之后再绑定。新增 `remote_agent_close` 和 `remote_agent_sessions`，spawn 与 message 可传 `lifecycle`，one-shot 终态后普通关闭。进程名额等待不再计入 60 秒，任务保持 `CAPACITY_PENDING`，并带队列位置和已等时长。关闭后的 message 接回原会话，并标明 `resumed`。persistent 的 ACP 会话在远端确认空闲后，超过 `sessionLifecycle.persistentIdleTtlSeconds`（默认 600 秒，`idleTtlSeconds` 可覆盖，0 不回收）由网关关闭，原因 `idle-ttl`。G9 未做。
