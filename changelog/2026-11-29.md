# 2026-11-29

## 新增

- 新增 `l1-gate.mjs` 的两项确定性机检（`BL-003`，`packages/service/test/l1-gate-hardening.test.ts` 为对应回归）：
  - 抽出共享基线 `resolveBaseline(dir, explicitBaseRef, anchorOk)`：`aoci_block_immutable`、`evals_immutable` 与 `--allowed-paths` 现在只认一条 fail-closed 锚点 `merge-base(HEAD, refs/remotes/origin/main)`。门禁从不 fetch，`origin/main` 缺失或过期即判失败；显式 `--base-ref` 必须解析到**同一个** merge-base，否则报错，因此传 `HEAD`、传本分支提交或传一个同样改过受保护路径的分支都无法把变更窗口挪走。
  - 新增默认始终开启的 `evals_immutable`：收集 `baseSha..HEAD` 已提交 diff、`--cached` 暂存区、工作区未暂存与 `status --porcelain=v1 -z -uall` 未跟踪的全部变更路径（含 rename/copy 的源与目标路径），任一命中 `/^\.1agents\/roles\/[^/]+\/evals(?:\/|$)/` 即返回 `{ id: 'evals_immutable', ok: false, baseRef, baseSha, violations }` 并以退出码 1 失败——任意角色的考卷目录都受保护，把考卷改名移走也算改动（diff 源路径命中）。仅显式 `--allow-eval-change`（只应由人批准 `eval_change` 提案后传入）放行并返回 `{ ok: true, overridden: true }`；缺少 `.git` 锚点或 `origin/main` 时与 `aoci_block_immutable` 一样 fail-closed。
  - 新增按需开启的 `--allowed-paths <spec>` 授权白名单：可重复传、可逗号分隔，支持精确文件路径、目录前缀（`dir/` 或裸目录名 `dir`）与标准 glob（`*` 单段、`**` 跨段）。传入时校验上述全部变更路径，任一越权即返回 `{ id: 'allowed_paths', ok: false, ..., violations }` 并退出码 1；缺参数值、空列表、绝对路径、含 `..` 越界或形似 flag 的条目一律报 `usage` 退出码 1。未传该参数时输出保持既有形状（不新增检查项，不阻断现有调用方与 `pr-delivery-projection.test.ts`）。
  - 顶部 usage 注释同步补充 `--allow-eval-change`、`--allowed-paths` 与共享基线的语义。
- 新增 `packages/service/test/l1-gate-hardening.test.ts`（4 项）：在临时 git 仓库里实跑真实 `l1-gate.mjs`，覆盖考卷未暂存/已暂存/已提交/未跟踪/改名移出五种形态、`--allow-eval-change` 豁免、缺 `.git`/缺 `origin/main` 的 fail-closed，以及白名单的精确路径、目录前缀、单段与跨段 glob、重复传参与 `usage` 失败路径。
- `packages/dsh-plugin/test/a2a-current-dsh.test.mjs` 新增 1 项：模拟真实 Cordis Proxy 的 `ctx.get`/属性 trap 三种组合（查不到且属性读取抛错、两者都抛、`ctx.get` 命中而属性 trap 抛错），断言前两种稳定返回 `code === 'SANDBOX_UNAVAILABLE'`，第三种优先走 `ctx.get('permissionPresets')` 装好预设且完全不触发属性读取异常。

## 调整

- `packages/service/src/a2a/session-hosts.ts`：`SessionDeliveryMode` 不再在本地重新声明字面量，改为 `import type { SessionDeliveryMode as L0SessionDeliveryMode } from '@1agents/dreammate-network'` 复用 L0 类型，新增 `SESSION_DELIVERY_MODES = ['queue', 'steer'] as const satisfies readonly L0SessionDeliveryMode[]` 钉住运行时取值，并把 `messageSchema.mode` 改为 `z.enum(SESSION_DELIVERY_MODES)`；`packages/service/src/a2a/session-delivery.ts` 的 `deliveryModeSchema` 与 `packages/service/src/a2a/gateway.ts` 的 `sessionDeliveryModeSchema` 同样改用该元组，消除本地漂移风险（L0 `protocol.md` §15）。
- 空 `correlation: {}` 服务侧归一化为 absent（`session-hosts.ts` 新增 `normalizeCorrelation`，`gateway.ts` 的 `session_message_send` 顶层回显、`session-delivery.ts` 的 `enqueue`/`enqueueTarget` 与加载路径，以及 `session-hosts.ts` 的 DSH 信封共同使用）：没有任何字段的 `correlation` 视为“无上下文”，不再出现在顶层返回、`session-delivery.json`、`SessionDeliveryReceipt` 或宿主投递信封——与 DSH `session-notice.ts` 及 L0 `protocol.md` §13 的“没有对应上下文就整个省略”保持一致。判等逻辑（同一 messageId 复用不同上下文即 `different content`）也改用归一化后的值。
- `packages/dsh-plugin/src/a2a-executor.ts`：`enforceSandbox` 改为在 `try/catch` 内优先通过 `ctx.get('permissionPresets')` 读取服务，缺失时才回退 `ctx.permissionPresets`；任何属性读取异常或缺失都统一收敛为 `sessionError('SANDBOX_UNAVAILABLE', ...)`。此前属性优先的写法在真实 Cordis Proxy 上会让未注册服务的属性读取异常绕过该错误码，把一个“只读沙箱无法落实”的拒绝演变成不可识别的异常；现在宿主永远拿到稳定错误码，且带真实 Cordis 类型时依然零 TS 报错。
- `docs/solutions/backlog.jsonl`：`BL-002` 置为 `status: "done"` 并补 `linkedPr: 40`、`mergeCommit: "433ee267c78dec4de05107120d891229c6742056"` 与 PR #40 三绿合入说明；`BL-003` 置为 `status: "in_progress"`（本 PR 未合并前不标 `done`），备注写明实现方式。

## 修复

## 不兼容变更

- `l1-gate.mjs` 默认输出新增 `evals_immutable` 检查项，并默认拒绝任何 `.1agents/roles/<role>/evals/` 变更；确实需要改考卷时必须显式传 `--allow-eval-change`（人工批准 `eval_change` 之后）。
- `--allowed-paths` 是新增开关，只在显式传入时出现对应检查项；不传时既有调用方（`checklist.json` 的 `l1-gate` runner、`pr-delivery-projection.test.ts`）的输出与退出码语义不变。
- `sessionSendSchema` 的校验语义不变（`correlation: {}` 仍被 schema 接受），但落盘与投递侧不再保留空对象；历史上已写入 `correlation: {}` 的 `session-delivery.json` 仍可加载，加载时会丢掉空对象并回写，因此旧记录重新入队仍保持幂等。
