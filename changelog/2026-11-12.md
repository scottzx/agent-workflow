- 调整：DSH 插件在诊断目录或 A2A 状态目录已被另一个存活实例占用时不再让插件启动失败。后启动的一端改为只读：A2A 能读已有任务，写入和 `recoverInterrupted` 直接拒绝，因此不会把所有者进行中的任务标成失败，也不会删掉对方的锁。诊断记录只留在该进程内存里，避免对话因为写不了共享诊断文件而失败。

- 新增：`scripts/sync-clash-tailscale-iface.sh`，用于在 Tailscale 网卡号漂移后同步 Clash Verge 配置里走 Tailscale 节点的 `interface-name`。从 `tailscale ip -4` 取本机 Tailscale 地址并用 `ifconfig` 定位承载网卡，用 `route -n get <peer>` 交叉核对到 Tailscale 节点的路由网卡，不一致时告警；只改写 `server` 落在 `100.64.0.0/10` 的节点，`interface-name: en0` 等其它绑定不动；备份写入 `$VERGE_DIR/backups/`，不污染 Clash Verge 的 `profiles/` 目录；默认只检查，`--apply` 落盘，`--reload` 顺带重启 Clash Verge 让改动生效。
- 验证：用 `IP_BOUND_IF` 分别绑定各网卡拨号复刻 mihomo 行为，`utun2` 得到 `[Errno 51] Network is unreachable`，`utun6` 连接成功，`en0` 超时；用 `/Applications/Clash Verge.app/Contents/MacOS/verge-mihomo` 起两份仅 `interface-name` 不同的配置做 A/B，`utun2` 返回 502 且日志为 `connect: network is unreachable`，`utun6` 返回 204 且出口 IP 为 `178.128.74.214`；`tailscale ping 100.92.59.9` 显示 WireGuard 直连 `178.128.74.214:41641`、140ms，证明隧道与服务端均正常；改动后经真实 Clash 复测，`claude.ai` 403、`api.anthropic.com` 404、`www.anthropic.com` 200、`www.gstatic.com` 204、`chatgpt.com` 200，出口 IP 恢复为 `178.128.74.214`；同步脚本在手动改回过期 `utun2` 后能自动纠正回 `utun6`，5 个 `interface-name: en0` 节点保持不变。
