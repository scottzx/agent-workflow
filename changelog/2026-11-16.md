# 2026-11-16 后续补记：交接与三种目录

## 新增

- 账本可以记录交接。`handoff_propose` 只提议把当前轮次已记录的产物交给另一个执行目标；`handoff_decide` 接受或拒绝。接受不会派下一单，下一单要另调 `execution_submit` 并带上 `handoffId`。
- `handoff_offer` 登记一条约定。验收通过或任务单关闭、且只有一条不要求人确认的约定成立时，账本记下已接受的交接，仍不派单。多条同时成立时不挑选。
- 工作台投影只画已经提议、接受或走成的交接。尚未发生的约定写在当前任务的 `legalNext` 上，不画成路径。
- 同一件事的目录分开。任务目录仍是 `<cwd>/.1agents/jobs/<jobId>/`。角色公开目录是 `<cwd>/.1agents/roles/<roleId>/published/`。`handoff_space` 把一个已有宿主目录登记为该 `caseId` 的共享产物空间；清单里的文件可以落在任务目录或这块空间，不能落在角色目录。

# 2026-11-17 补记：新增 launchd 服务模式（自动拉起但不持有）

## 新增

- `serviceMode` 增加 `launchd`：先探测 `serviceUrl/health`，健康的服务直接共用；无人应答时唤醒已注册的服务管理器（默认 label `com.1agents.acp-service`，可用 `serviceManagerLabel` 覆盖），等服务健康后返回。宿主**不持有**该进程，释放租约时不停止它，因此 DSH 重启不影响其它客户端。
- 唤醒先尝试 `launchctl kickstart -p`；若该服务在域中尚未加载（kickstart 返回 502），回退读取 `~/Library/LaunchAgents/<label>.plist` 并 `launchctl bootstrap` 后再 kickstart，覆盖机器重启后 plist 存在但未加载的情形。
- `serviceManagerLabel` 严格校验为纯 label 字符集（不允许 `/`、空格、`..`），因为它会作为参数传给 `launchctl`。

- 开关按**条目 id 与模块名断言**匹配，只更新**最后一个匹配覆盖**的 `disabled`，没有匹配则追加一条覆盖。
- 仅含 `id` + `disabled` 的覆盖，在 bundle 层与其余 profile patch 已给出目标状态时会被**移除**，因此 profile 只记录与 bundle 的差异。

- 移除 profile 覆盖后，`--dump-config` 中 `oneagents-acp` 仍解析为 `serviceMode: launchd`、`serviceManagerLabel: com.1agents.acp-service`，行为不变。
