# 工作台的智能体开发阶段与运行阶段

- 日期：2026-10-27（Asia/Shanghai）
- 状态（2026-10-28 更新）：任务与智能体两个模块、试跑/正式标记、草稿/命名发布，以及网关自带的独立页面，已提交到分支 `workbench-a2a-e2e-20261027`，并部署到本机测试环境（网关 :36814 的 `/workbench/ui/`；DSH web 里的插件已换成同一构建）。发布名字还没有同步进 DSH 的 `agent-session-settings.json`，执行宿主仍回放该工作区和 ACP Agent 最近一次已接受的设置。父应用 1agents_app 里的旧工作台页面和 Go 代理没动。分支未合并 main。
- 相关：[任务工作台](task-workbench-implementation-20261022.md)、[Grok 权限模式与工作台的两类人工事项](grok-mode-and-workbench-requests-20261027.md)

工作台仍是一个入口。里面两个同级模块：任务、智能体。智能体有开发阶段和运行阶段。试跑任务和正式任务都进任务清单，也都进同一个人的审核。

## 两个模块

| 模块 | 看什么 | 现有入口 |
| --- | --- | --- |
| 任务 | 每一轮派出去的工作 | 全部任务、待我确认、进行中、异常 |
| 智能体 | 系统里正在开发和已经上线的角色 | 新增，与任务清单同级 |

从智能体点进一条，看到它的配置和它名下的任务。这些任务就是任务清单里的同一条记录。任务清单继续收没有挂到智能体上的临时任务。

## 智能体的两个阶段

开发中的一条，是一个角色草稿加上它正在试的一个 ACP Agent。Grok Build 和 Codex 各自留自己的 mode 和配置。同一个角色同时试两个执行者时，开发中是两条。

已上线的一条，是发布时冻结的名字。一行名字就能固定调用。冻结内容是这个 Agent 当时接受的 `modeId` 和有序 `{id, value}`，模型在前。之后再改 ACP 设置，只改开发中的草稿。

已经在跑的常驻角色直接出现在已上线，不要求先补一次试跑。一个名字可以同时有正在跑的发布和一份更新中的草稿，模块里两行都在，并互相指向。

发布在智能体模块完成。试跑任务审核通过，只表示这一轮产物通过，不会自动把草稿上线。

## 任务清单

试跑任务挂在开发中的智能体上，正式任务挂在已上线的名字上。两条都是账本里的真实任务，用标记区分试跑和正式。

全部任务、进行中、异常都同时列出它们。待我确认也同时计入。打开一条时能看出它是试跑还是正式，以及属于哪个智能体。

## 人的审核

审核仍是现有两类，记录继续分开：

- 结果验收：绑定任务、轮次、版本和摘要。
- 过程请求：提问和计划审批，绑定当次请求。

试跑和正式都走这两类。待我确认是同一个队列，不按阶段再拆一个收件箱。2026-10-28 起工具审批也作为过程请求进入这个队列：可以附理由拒绝，或拒绝并停止任务；期限由网关 `workbench.requestTimeoutMinutes` 设置（测试环境 30 分钟）；新请求可弹 macOS 通知。结果验收在页面上只显示，仍由发起会话用 `execution_review` 记录，页面没有验收按钮。细节见 [Grok 权限模式与工作台的两类人工事项](grok-mode-and-workbench-requests-20261027.md)。

## 已接入

网关在 `agent-registry.json` 保存开发草稿和已发布名字。新任务按当时的目标归属打上试跑或正式，并冻在该次执行上。续跑沿用原标记。已有常驻角色没有草稿时，在已上线里按目标出现。父应用工作台在任务清单旁增加智能体模块，任务清单增加试跑、正式、临时。过程请求可以在任务详情里回答，不另发一条任务消息。审核通过不会调用发布。

`execution_submit` 仍不携带 ACP 目录。Grok 与 Codex 的选项继续分属各自的草稿。发布只复制这份工作台记录，并让之后打到同一执行目标的新任务变成正式。DSH 插件里的 `agent-session-settings.json` 仍是每个工作区、每个 Agent 一份最近记录，下一次 ACP 设置仍会改它。

## 独立页面（2026-10-27 晚）

工作台不再依附父应用。2026-10-28 起已部署到本机测试环境。A2A 网关自己在 `/workbench/ui/` 提供页面，读写的仍是同一份账本和 `agent-registry.json`。配置了 `workbench.token` 时，页面登录用它换会话 cookie，bearer 接口也要它；在可信网络里可以不配，页面免登录、接口不校验 bearer。测试环境现在不配令牌。网关只监听 127.0.0.1。无论有没有令牌，页面写操作都要求同源浏览器。生产环境改用账号体系，不再用这个令牌。父应用和驾驶舱最多保留一个链接，不再各自维护工作台页面和代理。父应用里的旧页面与 Go 代理待确认后移除。
